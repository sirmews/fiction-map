# articy:draft

## Classification

- **Nature:** full narrative design platform
- **Relevance:** high strategically, low tactically

## Official sources

- [articy:draft home](https://www.articy.com/en/)
- [Scripting in articy:draft](https://www.articy.com/help/adx/Scripting_in_articy.html)

## What it is

articy:draft is a professional narrative design system for interactive projects.

The official site and help center show a platform with:

- narrative design tooling
- flow authoring
- object templates
- entities, locations, documents, localization
- scripting
- engine exports and technical exports
- multi-user collaboration

## Authoring model

articy combines:

- flow-based authoring
- object/template-driven data modeling
- scriptable logic

This makes it much more expansive than a lightweight story graph engine.

## Runtime/integration model

articy is export- and integration-oriented rather than a minimal headless package model.

Its help center and product surface emphasize:

- engine exports
- technical exports
- scripting
- integration workflows

## What transfers cleanly to Fiction Map

- distinction between templates/schemas and authored instances
- serious export discipline
- simulation/scripting as part of the content workflow

## What does not transfer cleanly

- massive ontology surface
- enterprise workflow complexity
- multi-user and organization-oriented features

## Traps to avoid

- pushing too much domain into the engine core
- creating a huge built-in model for characters, quests, items, lore, etc.
- optimizing for enterprise workflow before validating the engine boundary

## Judgment for Fiction Map

articy is useful as a long-range product reference and a reminder that template/schema
discipline matters.

It is a poor short-range implementation model for a solo-built headless framework.
